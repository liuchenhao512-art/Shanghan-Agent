# 伤寒论智能体

本地运行的《伤寒论》经典阅读、个人专题资料管理与有出处的学术研读工具。

源码仓库：[liuchenhao512-art/Shanghan-Agent](https://github.com/liuchenhao512-art/Shanghan-Agent)。仓库包含代码、构建配置、文档、内置语料、图标及已有验证材料；个人资料、模型密钥、知识库备份、依赖环境、测试缓存和旧文件夹不上传。安装包与打包目录保留在本地，GitHub源码仓库不包含 `dist`；从仓库下载后请按下文配置开发环境或自行构建。

## 使用者入口

本地Windows试用安装包为 `dist/Shanghan-Agent-0.3.3-win-x64.exe`。0.3.3为知识库增加右侧“⋯”管理菜单，可直接预览删除；清理对话中的重复引用占位和开头固定说明，将参考资料集中在回答底部。正常对话与按需RAG继续保留。运行环境已包含在安装包中；这是未签名试用构建，干净系统安装、真实模型研读与 Mac 实机验收仍待进行。具体状态见 [项目计划](PROJECT_PLAN.md) 和 [本轮改版记录](验证记录/知识库管理与回复显示验收_2026-10-11.md)。

1. **经典研读**：离线阅读398条条文、九家注解、原书、教材解析及关联条文。未配置模型时也可检索。
2. **我的知识库**：左侧“知识库”旁点击“＋”，例如创建“近现代伤寒专著知识库”，按类别导入著作和文章。输入名称后一次确认创建；导入资料仍需核对正文与来源后确认。确认入库后即成为可检索资料，在专题对话的“资料范围”中选择该库即可使用，也可同时选择多个库。未选择的库不参与该条消息的检索；空库需先添加资料。创建知识库不会自动创建研究专题。
3. **专题研究**：点击“新建研究专题”，例如建立“桂枝汤证不同解释”，即可正常交流、解释概念或连续追问。Enter发送、Shift + Enter换行。“资料范围”可选择一个或多个知识库及内置经典；取消全部选择可仅使用模型对话。需要具体条文或注家观点时，模型按问题检索所选范围。回答直接呈现正文，底部“参考资料”可点击打开原文；没有有效引用时显示“本次未引用知识库资料”。书目查询会注明仅查看目录、未引用正文。
4. **按需检索与研读**：模型可拆分短关键词、限定作者或资料、翻页查阅，检索结果均衡覆盖不同作者。书目问题使用所选库的真实目录。检索未命中仍可用模型知识交流，但不能据此认定某位作者没有相关论述。不设固定研读轮数上限，可以随时停止或继续；停止、退出或调用失败后保留进度，重启不自动调用模型。
5. **重命名与归档**：在知识库或研究专题名称右侧点击“⋯”，选择“重命名”或“归档”，核对后确认；不必先切换到该项目。两类项目互不联动改名。左侧底部“已归档的知识库／研究专题”可查看、恢复或删除。归档完整保留资料，不自动清空；归档库恢复后才能用于新的对话，已有引用和历史任务固定范围仍保留。归档专题恢复后可继续对话。
6. **删除**：知识库与研究专题均可直接从右侧“⋯”菜单选择“删除…”，也可在归档列表删除。核对具体影响范围后确认，取消不改变内容。删除研究专题会删除其对话、草稿、笔记和专题文件夹，引用的独立知识库保留。删除后不能从应用恢复。删除知识库时，其他库共享的资料、历史引用及已有任务固定范围所需的原文继续保留；无关联资料的原件和正文才会清理。
7. **专题成果与正式笔记**：对话和草稿自动保存。“我的知识库”左侧“专题成果”展示每个研究专题的独立文件夹；也可从研究页右上“专题文件夹”打开。点击回复出处核对原文，确认后保存正式笔记。支持Markdown/PDF导出；Markdown旁的附件文件夹应一起保存或分享。AI成果不作为新的独立原始证据。
8. **设置与备份**：填写兼容接口服务地址、模型名称和自己的密钥；密钥由系统加密。知识库备份包含资料、独立专题、归档状态和引用，默认不含密钥。恢复先核验，再写入独立目录；原数据保留。

支持文字 PDF、EPUB、DOCX、TXT、Markdown 和指定网页。单份文件上限100MB。旧版 `.doc` 需另存为 `.docx`；扫描件请通过外部识别工具转换后导入。PDF页码指文件页序，其他格式采用章节或段落定位。网页访问受限时改用文件导入。

原始资料与AI笔记分别保存。自动引用检查只能证明引文位置和字面可核对，不能代替学术审阅；未核验的模型回答也不能视为某位注家的原文观点。程序不会主动联网寻找研究资料；调用在线模型时，必要片段会发送到用户选定的模型服务。

升级后已有对话会以新版简洁格式显示，原始草稿与人工编辑的正式笔记保持原样。旧笔记和已经导出的文件不会被自动改写；新回复保存及导出采用新版格式。未配置模型时仍可离线阅读、检索与导入，正常对话需要在应用“设置与备份”中配置服务。

## 开发与构建

开发环境：Python 3.12、Node.js 22.12以上；本次使用 Python 3.12.14 与 Node.js 26.7.0。

Windows：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
npm ci
node node_modules/electron/install.js
npm start
```

macOS（在对应架构的 Mac 上运行）：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
node node_modules/electron/install.js
npm start
npm run build:mac:arm64  # Apple Silicon
# Intel Mac 使用 npm run build:mac:x64
```

Windows 构建：`npm run build:win`。Python 后端由 PyInstaller 打包，安装器由 electron-builder 生成。不要将 Windows `.venv`、`node_modules` 或冻结后端直接复制用于 Mac 构建。macOS 最终安装与主要功能必须在对应 Mac 上验收。

已安装依赖使用 `package-lock.json` 和 `requirements.lock.txt` 记录；后者为本次 Windows 环境快照，macOS 依照 `requirements.txt` 解析平台依赖。

## 验证

已确认图标及各平台格式位于 `resources/icons`，其中 `source.png` 是用户上传原图，`icon.ico` 供 Windows 使用，`icon.icns` 供 macOS 构建使用。根据用户要求，导出图标采用透明圆角方形，圆角半径为边长的16%；保留原图及字体，不重绘图案。正常打包直接使用已有图标；需要重新编码时，在已安装 Pillow 的 Python 环境运行 `python scripts/build-icons.py`。Mac 图标资源已准备，最终显示仍需 Mac 本机验收。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests -q
npm test
.\.venv\Scripts\python.exe -X utf8 scripts/qa-fixtures.py
node scripts/qa-electron.cjs
node scripts/qa-electron.cjs --packaged
```

桌面自动化使用独立 `.test-data` 目录及本机确定性模型，不会使用真实密钥或消耗模型额度。测试模型的输出均标记为程序验证，不能当作学术研究成果。

## 工程结构

- `desktop`：桌面生命周期、系统密钥存储、受限文件与导出接口。
- `server`：原功能兼容层、个人库、提案事务、导入、模型与研读任务、备份恢复。
- `ui`：经典界面与四工作区界面。
- `resources/builtin`：从原项目独立复制的只读语料及迁移校验清单。
- `scripts`、`tests`：构建与验证入口。
- `验证记录`：测试报告、界面截图和明确标记的程序验证样稿。

不读取、复制或分发原项目 `.env`。个人资料、密钥、测试目录与安装包均不应混入公开源码仓库。当前项目不包含自动更新或公开发布流程。

默认个人资料保存在系统应用数据目录中的 `ShanghanAgent/library`。Windows 通常位于 `%APPDATA%\ShanghanAgent\library`，macOS 通常位于 `~/Library/Application Support/ShanghanAgent/library`；以“设置与备份”中显示的实际路径为准，可打开或切换资料目录。备份默认不包含模型密钥，换电脑后重新配置。

专题文件夹实际位于个人资料目录的 `专题/名称-稳定标识/`，包含 `对话记录.md`、`专题记录.json`、`资料清单.json`、`研读草稿` 和 `正式笔记`。原件仍由资料目录统一管理，避免跨专题重复复制。数据库是正式记录，文件夹为自动更新的可读副本，编辑内容请通过应用完成。

从0.1.x或0.2.0首次启动0.3.0时，会在个人资料目录的 `migrations` 中保存迁移前数据库副本，再升级为独立的知识库与研究专题。旧名称、标识、资料归属、对话、笔记和引用保留，旧版同名项目在升级后可以分别管理；不自动合并或清理用户内容。专题文件夹沿用稳定路径，改名会更新其中的标题与记录，避免移动路径影响历史定位。

每次新版交付核验后，旧版安装包、源码包、配套校验文件及被替代的旧版交付文档会集中放入项目根目录的 `旧文件_待手动删除_日期_版本号`，由用户手动删除。当前源码、有效文档及个人运行数据继续保留。Windows收纳脚本为 `scripts/archive-old-releases.ps1`，要求当前版本发布清单及文件校验通过后才移动旧文件，并保存逐项清单。
